# agent_metadata：这套规范解决什么问题

`agent_metadata` 用来保存可迁移的智能体过程资产：专家身份、技能、外部工具需求、配置契约和工作区种子文件。它把这些内容留在一个框架无关的包里，让新的 Agent 实现能够根据自身能力完成适配。

这套规范来自一个很实际的问题。dedge 的智能体曾分别运行在 OpenCode 插件、Hermes project-local home 等环境中。每换一次宿主，身份提示、技能和项目资产就要重新整理，久而久之容易丢失，也很难知道哪一份才是准的。

## 它不负责什么

`agent_metadata` 不是编译器、安装器、运行时，也不是某个 Agent 的配置格式。它不会规定固定的安装命令，更不会替某个宿主生成最终配置。

包内资产是来源；在 Hermes、OpenCode 或其他宿主中生成的 profile、agent、preset 和配置都是派生产物。派生产物可以重建，不应反过来成为唯一维护点。

## 包里有什么

- **能力域**：专家身份、边界、协作方式，以及可直接复制到目标工作目录的持续性项目/目录约束；其宿主部署位置由自举规约决定。
- **技能**：可按需加载的能力目录，包含入口、参考资料、脚本和资源。
- **MCP 声明**：需要接入什么工具、使用什么命令和变量，不含宿主专有配置。
- **环境契约**：部署时需要的变量和凭证说明，不含真实值。
- **工作区资产**：需要落到项目里的模板、目录或运行种子。
- **Adapter**：为了让元数据包在特定宿主上集成而需要的全部宿主专用内容，包括适配说明、脱敏配置示例、集成实现源码、构建配置和辅助脚本。
- **验证用例**：可重复的迁移验收契约；确认自举结果真的能被宿主使用。

目录和机器可读字段见[包结构与元数据](01-package-and-metadata.md)。部署语义与安全边界见[自举、适配与安全](02-bootstrap-and-security.md)。

## 自举的基本路径

```text
读取 README、package-metadata.json 和 BOOTSTRAP.md
    ↓
识别当前宿主及其实际能力
    ↓
选择能力域，确认目标工作区和修改范围
    ↓
按需收集配置，将资产映射到宿主
    ↓
检查技能、MCP、环境和工作区资产是否真的生效
```

Adapter 文档能节省摸索时间，但不是事实来源。遇到版本差异时，应以当前宿主的官方文档、配置格式和实际运行结果为准。

## 使用边界

适合：团队有多个专家角色、会更换 Agent 框架，或希望把已有能力作为可交接资产保存。

不太适合：只有一个稳定宿主、资产只是少量提示词，或需求本身是一次性、固定的部署脚本。



## 版本

当前规范版本为 `0.2.1`（协议版本 `0.2`）。协议版本与包内容版本分开维护，规则见[发布与验证](03-release-and-verification.md)。版本间的规则变更记录见根目录 [CHANGELOG.md](../CHANGELOG.md)。字段明细、历史项目映射和术语已融合在前三篇规范中。
